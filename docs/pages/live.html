Live streams

Describe a stream while it plays: every frame a sampler keeps is answered as soon as it arrives, not when its chunk ends.

Running one

from vidra import LocalEmbedder, Models, OpenAI
from vidra.video_rag import video_rag_live

def check(o):                                   # every answer, as it is ready
    if o.structured.get("rule") == "no_hard_hat":
        print(f"{o.seen_at}  chunk {o.chunk_id}  t={o.media_ts:.1f}s  {o.description}")

run = video_rag_live("tcp://0.0.0.0:9000?listen=1", "data/out", video_id="dock-3",
                     sampler="clip:safety", on_unit=check,
                     models=Models(vlm=OpenAI(), embedder=LocalEmbedder()))
print(run.observations, "answers,", run.dropped, "dropped, lag", run.lag_s)

The call blocks until the stream ends. Detection belongs in your on_unit: the pipeline describes and embeds, your application decides what counts as an event. An exact match on a one_of field (fields) is more reliable than comparing vectors: embeddings handle negation badly, so "wearing a hard hat" and "without a hard hat" sit close together.

Testing with a file

A complete run, sender and both searches included, is the live recipe.

live.send pushes a file to a port at the pace it was recorded. The receiver loads its samplers' models before it listens (about 20-35 s for clip, yolo and objects), so the sender retries for up to connect_timeout_s.

import multiprocessing
from vidra.video_rag import live, video_rag_live

if __name__ == "__main__":
    sender = multiprocessing.Process(target=live.send,
                                     args=("samples/test.mp4", "tcp://127.0.0.1:9000"),
                                     kwargs={"speed": 1.0})
    sender.start()
    run = video_rag_live("tcp://127.0.0.1:9000?listen=1", "data/out", video_id="test-live")
    sender.join()

Run the sender in its own process, as a camera would be: while it waits to connect, PyAV holds the GIL, and on a thread of the same process it slows the receiver's model loading many times over.

send(path, url, speed=1.0, connect_timeout_s=120.0, format=None) copies the picture without re-encoding, into MPEG-TS for H.264, HEVC and MPEG-2/4 and into Matroska for the rest (VP9, AV1); format= overrides. A codec this PyAV cannot write (Theora) is refused: re-encode it first. A file path is also a valid source: it is then read as fast as it decodes, which keeps exactly the frames video_rag keeps with the uniform policy.

Sources are anything PyAV opens: tcp://host:port?listen=1, udp://, rtmp://, an rtsp:// camera. The PyAV wheels have no SRT.

Frames only

To run a model of your own on a stream, such as a person tracker, read its frames with the clock and rules video_rag_live uses, without samplers or a model call:

live.frames(url, per_second=None, open_timeout_s=60.0, read_timeout_s=10.0, gap_s=2.0) -> Iterator[tuple[Frame, Arrival]]
from vidra.video_rag import live

for frame, arrival in live.frames("rtsp://camera-2/stream", per_second=5):
    tracks = tracker.update(frame.image)       # BGR pixels
    log(arrival.seen_at, frame.media_ts, tracks)

Each frame is a video.Frame, with media_ts counted from the first frame. Each live.Arrival carries seen (time.perf_counter() at decode), seen_at (UTC, ISO 8601) and gap_before (the clock jumped more than gap_s just before this frame). A packet the decoder rejects is skipped. The stream opens when the first frame is asked for and closes when the loop ends, break included; it ends by itself when the sender stops or nothing arrives for read_timeout_s. A file is read as fast as it decodes.

What each answer carries

ObservationIs
chunk_id, media_ts, frame_indexWhere the kept frame is.
sampler_id, sampler, questionWhich answer this is, as in video_rag.
frames, frame_tsEvery frame the model was shown, in time order, each once: views made from a frame are not listed.
description, structuredThe answer.
content, vectorWhat was embedded, and its vector.
seen_at, answered_at, lag_sWhen the frame arrived and when its answer was ready (UTC), and the seconds between.
gap_beforeThe stream's clock jumped just before this frame.

Each one is also appended to observations.jsonl as it arrives.

Context frames

One frame cannot show movement. context=(1, 0) sends the previous decimated frame too; (0, 1) the next one; (1, 1) both. A frame after the kept one delays its answer by one decimation interval (1 s at per_second=1); frames before cost nothing but tokens.

When the model falls behind

If frames are kept faster than the model answers, the oldest waiting frame is dropped and counted in run.dropped; the lag stays bounded instead of growing. To keep up, raise the model's concurrency, keep fewer frames (min_interval_s, max_per_chunk on the sampler), or lower per_second.

When the stream ends

The run is written as media.json, timeline.json, manifest.json, descriptions.json and embedded.json, so search and aggregates read it like any other video. A chunk's description there is its frames' answers joined in time order, and each answer is kept whole under observations.

LiveRunIs
endedended, stopped, stop_after_s or error.
observations, failed, droppedAnswers written, model calls that failed (the run goes on), frames dropped from the queue.
written, unwrittenAnswers that reached database as they arrived, and those that did not.
lag_sSeconds from arrival to answer: p50, p95, max.
gapsWhere the stream's clock jumped.
duration_s, chunks, frames_decimated, frames_sampledHow much was read.
recording, steps, problemsThe recording's path, the documents written, and what failed.

An exception from on_unit (other than StopStream) stops the run, and is raised after the documents are written.

Writing to a database as it runs

from datetime import datetime, timedelta, timezone
from vidra import LocalEmbedder, Models, Supabase
from vidra.video_rag import search_observations, video_rag_live

db = Supabase()
models = Models(embedder=LocalEmbedder())
run = video_rag_live("rtsp://dock-3.local/stream", "data/out", video_id="dock-3",
                     sampler="clip:safety", models=models, database=db)

# from anywhere, while it runs: the last ten minutes on dock-3
hits = search_observations("liquid spilled on the floor", "dock-3",
                           since=datetime.now(timezone.utc) - timedelta(minutes=10),
                           models=models, database=db)
for h in hits:
    print(h.seen_at, h.media_ts, h.frame_index, h.description)

With database=, every answer is sent as it arrives (write_observations): at once when the database keeps up, the backlog in one call when it does not. The video's row is written when the stream opens. A write that fails is counted in run.unwritten and the run goes on; every answer is still in observations.jsonl. When the stream ends, the batch documents follow, so search finds the run by chunk too.

Logging important moments

To catch moments close to ones you describe (a worker without a hard hat, a spill, a blocked exit) as they happen, subclass your database and look at each answer in write_observations before it is stored. Nothing else is needed: the live run already calls it with every answer moments after it exists.

  • It runs off the stream. The hook is called from the run's writer thread, so slow matching never delays answers.
  • A bug in it does not stop the run. An exception is counted in run.unwritten; catch your own errors, as below, so the answers are still stored.
  • One run calls it one batch at a time. A database shared by several runs (several cameras) is called by each run's writer at once, so guard any state with a lock.

Ask a question whose answers are easy to check, then check them two ways:

  • Rules, exactly: one fixed-choice field per rule, with a way to say "cannot tell". row["structured"]["hard_hats"] == "a member of staff without one". Rules never go through similarity: embeddings handle negation badly, so "a worker without a hard hat" and "a worker wearing a hard hat" come out close. Without a "cannot tell" choice the model guesses: asked for a list of missing equipment, it reported missing safety glasses on 40 of 93 frames of a building site where nobody's eyes can be seen at that distance, and missing gloves on workers visibly wearing them. With one field per item and "cannot tell", it chose "cannot tell" 10 to 43 times per camera and the moments fell from 244 to 72. Ask only about what the camera can resolve (a hard hat, a vest), and say who counts: asked about "workers" in a shop, it counted the customers.
  • Everything else, by similarity to each listed hazard, not to the whole answer. An answer is a paragraph about everything in shot, and one detail barely moves its vector: against whole answers, true ladder sightings scored at most 0.654 and a title card 0.653. Against each hazard on its own, true matches scored 0.83 to 0.91 ("worker on step ladder" 0.886, "wet floor sign" 0.911), and the closest false ones 0.75 to 0.81 ("stacked pallets" as a blocked exit, "scattered materials on floor" as a spill), hence 0.85 below. Measured with LocalEmbedder: a threshold belongs to an embedder and to footage, so measure your own.

The model's judgement is the limit: checked against the frames, a "without a hard hat" flag on a building site was right (two of three workers in soft caps), and an "everyone wears one" on a warehouse frame was wrong (the driver in the cab was bare-headed). Treat a moment as worth a look, not as a verdict.

docs/pages/examples/live_moments.py
"""Log the moments a live stream shows that match ones you describe, as they
arrive: a Supabase subclass that looks at each answer before storing it.

    python live_moments.py rtsp://camera/stream     # or a file, read as a stream
"""

import json
import sys
import threading

import numpy as np

import vidra
from vidra import LocalEmbedder, Models, OpenAI, Supabase
from vidra.video_rag import describe, video_rag_live

vidra.configure(env_file=".env")

# A question whose answers are easy to check: one fixed-choice field per rule,
# each with a way to say "cannot tell" (without one, the model guesses), and a
# list of hazards, each a short phrase, for everything else.
SEEN = ["every member of staff wears one", "a member of staff without one",
        "cannot tell", "no staff visible"]
describe.add_question(
    "ppe",
    "These {n} frames span {span}. Describe the staff at work (not customers or "
    "visitors) and any safety hazards.",
    fields={
        "hard_hats": {"type": "text", "about": "hard hats on the staff", "one_of": SEEN},
        "hi_vis": {"type": "text", "about": "high-visibility vests or clothing on "
                   "the staff", "one_of": SEEN},
        "hazards": {"type": "list", "about": "each hazard visible, in a few words"},
    },
)
RULES = {"hard_hats": "no hard hat", "hi_vis": "no high-visibility clothing"}

# What to look for among the hazards, matched by similarity.
TARGETS = {"spill": "liquid spilled on the floor",
           "blocked_exit": "boxes or a pallet blocking a doorway",
           "ladder": "a person working on a step ladder"}


class Moments(Supabase):
    """Supabase, plus: every answer that breaks a rule or names a hazard close to
    a target is logged as a moment before it is stored."""

    def __init__(self, targets, embedder, threshold=0.85, log="moments.jsonl", **kwargs):
        super().__init__(**kwargs)
        self.embedder = embedder
        self.names, self.targets = list(targets), self._unit(list(targets.values()))
        self.threshold, self.log = threshold, log
        self.lock, self.found = threading.Lock(), 0

    def _unit(self, texts):
        vectors = np.array(self.embedder.embed(texts))
        return vectors / np.linalg.norm(vectors, axis=1, keepdims=True)

    def write_observations(self, video_id, rows):
        try:
            self.record([m for row in rows for m in self.matches(video_id, row)])
        except Exception as exc:         # a bug here must not stop the storing
            print("matching failed:", exc)
        super().write_observations(video_id, rows)

    def matches(self, video_id, row):
        moment = {"video_id": video_id, "frame_index": row["frame_index"],
                  "media_ts": row["media_ts"], "seen_at": row["seen_at"],
                  "description": row["description"]}
        for field, target in RULES.items():
            if row["structured"].get(field) == "a member of staff without one":
                yield {**moment, "target": target, "matched": field, "similarity": None}
        # Each hazard on its own: a whole answer is a paragraph about everything
        # in shot, and one detail in it barely moves its vector.
        hazards = row["structured"].get("hazards") or []
        if hazards:
            similar = self._unit(hazards) @ self.targets.T          # hazards x targets
            for h, t in zip(*np.nonzero(similar >= self.threshold)):
                yield {**moment, "target": self.names[t], "matched": hazards[h],
                       "similarity": round(float(similar[h, t]), 3)}

    def record(self, moments):
        # Several runs may share one database, each writing from its own thread.
        with self.lock, open(self.log, "a", encoding="utf-8") as out:
            for m in moments:
                out.write(json.dumps(m) + "\n")
                print(f"{m['seen_at']}  {m['video_id']}  t={m['media_ts']:.1f}s  "
                      f"{m['target']}: {m['matched']}")
            self.found += len(moments)


embedder = LocalEmbedder()
database = Moments(TARGETS, embedder)
run = video_rag_live(sys.argv[1], "data/out", sampler="clip:ppe", context=(1, 0),
                     models=Models(vlm=OpenAI("gpt-5.4-mini"), embedder=embedder),
                     database=database)
print(f"{run.observations} answers, {database.found} moments, "
      f"{run.written} stored as they arrived, lag {run.lag_s}")

To keep the moments in Supabase instead of a file, create a table and insert into it from record:

create table if not exists vidra.moments (
  video_id text, frame_index bigint, media_ts double precision, seen_at timestamptz,
  target text, matched text, similarity real, description text,
  primary key (video_id, frame_index, target, matched)
);
    def record(self, moments):
        if moments:
            self.writer().table("moments").upsert(moments).execute()

Subclass Folder or Database instead of Supabase to run without a server; send the moments anywhere (a webhook, a chat message, a queue) the same way.

How it differs from video_rag

  • No audio. Speakers can only be told apart over the whole recording. Record the stream and run video_rag on the recording afterwards for the transcript.
  • Uniform chunks only, and a short last chunk is not merged into the one before.
  • Time starts at the first frame. A jump forward of more than 2 s is a gap; a jump backward (a reconnect) continues the clock instead of going back.
  • Damaged packets are skipped and counted in the manifest, not fatal.

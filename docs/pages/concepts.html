Concepts

Chunks, output files, answer ids, vectors and reuse.

Two tiers

video_rag reads the video: eight stages, each reading files and writing one, ending with every chunk described and embedded. It also does search.

aggregates reads only the files video_rag wrote, never the video, and answers questions about the whole: counts, summaries, chapters, people.

workflow runs both in one call (The pipeline).

The chunk grid

A video is cut into chunks: consecutive spans, typically 5 to 30 seconds, stored in timeline.json. Everything after is keyed by chunk_id: frames, transcript, descriptions, vectors. Chunk 7 is the same seconds in every file, and a search result is a chunk.

The policy decides where boundaries fall:

PolicyCuts atNeeds
uniformevery chunk_s seconds (default 20)nothing
scenecuts in the picturea scene-detection pass
vadpauses in speechthe transcript
speakerchanges of speakerthe transcript, with speakers

Chunks are kept between min_s and max_s: short ones merge, long ones split evenly, and a short last chunk joins the one before (boundaries).

Video ids

The id is the folder name: the filename stem (shop.mp4 is shop) unless you pass video_id=. Allowed: ASCII letters, digits, -, _, ., not starting with _. A file like My Video!.mp4 needs an explicit video_id=.

The same file again reuses its folder. A different file with the same id gets a new one (shop-2), unless on_conflict is "replace" (deletes the old folder) or "refuse" (raises). Read the id from run.video_id.

Frames, samplers and questions

The video is decoded once and frames are offered at per_second (default 1). A sampler picks which to keep: every Nth (uniform), or when the scene, people, objects or on-screen text change (clip, yolo, objects, text). Samplers.

A question is what the vision model is asked about those frames, and the fields its answer fills. Each sampler has its own; any sampler pairs with any question as sampler:question. Questions.

Answer ids

Each answer is stored under an answer id, the sampler and the question:

Sampler specAnswer ids
clipclip (its own question)
uniform:textuniform:text
clip:[text,scene]clip:text, clip:scene, from one pass
clip,clip:checkoutclip, clip:checkout, from one pass

A chunk's transcript has the id transcript. Search filters and aggregate inputs use these ids.

Units and vector spaces

A unit is one piece of embedded text: one answer for one chunk (its prose plus its fields), or one chunk's transcript. embedded.json holds every unit and its vector.

Each vector is tagged with its embedder's key, e.g. local:BAAI/bge-small-en-v1.5:384. Vectors under different keys are never compared: search with the embedder that built the index.

Reuse

Expensive work is reused when nothing it depends on changed:

  • A description: same frames, same vision model and settings, same question wording. Editing one question re-describes only its answers.
  • A vector: same text, same embedder key.
  • An aggregate answer: same text read, same definition, same model key.

The pipelines do this automatically. Stages and aggregators called directly take previous=, the earlier output (usually the file being overwritten).

Model keys

Every model has a key, e.g. openai:gpt-5.4-mini, stored with each answer and vector and compared for reuse. In your own model class, change the key when the model changes, or old answers are reused as the new model's. Models.

Files first, database second

Every stage writes a file. With a database, the pipeline also sends each new document to it. A failed database write goes into run.problems and the run continues; the files are complete either way.

Search reads from a database. Folder reads the output folder in place, so search works without a server. Databases.

Errors

Everything raised on purpose is a vidra.VidraError. Two branches worth catching:

  • vidra.Unavailable: something is missing (a package, weights, a key, a server). Retrying won't help.
  • Refused: the request is invalid, e.g. min_s above max_s. Also a ValueError.

Most problems are caught before work starts: unknown questions, settings no sampler reads, missing keys. Full list: Reference.

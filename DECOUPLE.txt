DECOUPLING THE COMPONENTS
=========================
An implementation plan for plan.txt sections 1, 2, 3, 5, 7, 8, 9.
Sections 4 (async) and 6 (sampler grammar) are deliberately out of scope.

Two public levels, stated plainly:

    LEVEL 1   one component.  Either addressed by video id (`run`/`load`,
              reads and writes the data root) or handed its inputs directly
              (the pure verb below, which touches no filesystem at all).
    LEVEL 2   the whole pipeline, which is a loop over level 1.

The point of this plan is the parenthesis on level 1: today a component can
only be reached through the data root, so "use one component" and "adopt the
pipeline's directory layout" are the same decision. They should not be.


0. WHAT IS ALREADY TRUE  (so none of it gets rewritten)
=======================================================

The work is already factored out of every driver. Each of these takes objects
and returns an object, and none of them reads the data root:

    media/split.py       split(path, video_id) -> Media
    audio/reader.py      listen(uri, transcriber, diarizer, video_id) -> RawTranscript
    boundaries/scenes.py detect(media, stride, threshold, detect_width) -> Cuts
    boundaries/speech.py detect(raw, policy, silence_s) -> Cuts
    boundaries/grid.py   build(video_id, policy, duration_s, cuts, ...) -> Timeline
    video/pipeline.py    ingest(media, timeline, samplers, per_second,
                                store, store_scope, on_chunk) -> Manifest
    cut/cutter.py        to_chunks(raw, timeline) -> list;  stats_for(...)
    describe/reader.py   answer(manifest, timeline, describer, source,
                                samplers, existing, limit) -> Descriptions
    embed/units.py       from_descriptions(doc) -> list[Unit]
                         from_transcript(doc) -> list[Unit]

So a driver is already load -> compute -> write. This plan does not refactor
that; it publishes the middle, and moves the argument checks into it so both
ways in get them.

`pipeline.ingest` even takes an `on_chunk` callback already. Nothing passes
one. Section 4 below is largely a matter of wiring it up.

Two things are genuinely not decoupled, and they are the real work:

    the frame store   `FrameStore` is constructed from `paths.artifact(id,
                      "store")` in video's driver, and `FrameSource` resolves
                      the same path again in describe's. Pixels are the one
                      thing components hand each other that is not a document.

    every path        `paths.out_root()` is a process-global resolved from a
                      module-level dict. Two data roots in one process is not
                      expressible.


1. THE PURE LAYER -- one verb per component
============================================

Each component gains one name beside `run` and `load`: the function that does
its work on objects it is handed. `media.split` is already exactly this and
stays the model.

    media       split(path, video_id=None)                    -> Media
                (exists, unchanged)

    audio       listen(media, transcriber=..., diarizer=...,
                       model=None, language=None, vad_filter=None,
                       compute_type=None, device=None,
                       diarizer_model=None, exclusive=None)   -> RawTranscript

    boundaries  detect(policy, media=None, transcript=None,
                       stride=..., threshold=..., detect_width=...,
                       silence_s=...)                         -> Cuts | None

                timeline(media, policy="uniform", cuts=None,
                         chunk_s=20.0, min_s=5.0, max_s=None) -> Timeline

    video       ingest(media, timeline, sampler="uniform",
                       per_second=1.0, every_n=None, ...,
                       frames=None, store_scope="sampled")    -> Manifest

    cut         apply(timeline, raw)                          -> Transcript

    describe    answer(manifest, timeline, frames,
                       describer=None, samplers=None, limit=None,
                       existing=None, max_output_tokens=None) -> Descriptions

    embed       encode(descriptions=None, transcript=None,
                       embedder=None, batch=64)               -> list[Unit]

    retrieve    unchanged -- `search` already takes a query, not an id.

Rules these all obey:

  - They return the typed document, never `Produced`. `Produced` is a receipt
    for a write, and these do not write.
  - They read nothing and write nothing. No `sink=` parameter: a caller that
    wants a file calls `run`, or `sinks.write_json` itself. Adding `sink=`
    here would put the data root back into the signature, which is the whole
    thing being removed.
  - They do not need `configure()` to have been called.
  - They hold *all* of the component's argument validation -- the refuse-
    don't-drop tables (`SAMPLER_SETTINGS`, `EVIDENCE_SETTINGS`, the settings
    routing in audio), the question vocabulary check, `limit < 1`, `batch < 1`,
    `providers.require`, `min_s > ceiling`. `run()` then gets them for free by
    calling through. This is the level-asymmetric-validation trap in CLAUDE.md
    generalised: a check that lives in only one of two public paths is a check
    half the callers walk past.
  - `run()` is rewritten as: resolve inputs via the other components' `load`,
    call the verb, `sinks.write`, build `Produced`. Nothing else.

Naming collisions, and how each is settled:

  - `audio.listen` vs `audio/reader.py:listen`. The driver's takes a Media and
    setting *names*; the reader's takes built model objects. Same name, two
    functions -- which is the infinite recursion CLAUDE.md records for
    describe's second `describe`. Settled by importing the reader's under a
    private alias, not by renaming a module function the rest of the tree
    already calls `listen`.
  - `video.ingest` vs `video/pipeline.py:ingest` -- same, same fix.
  - `describe.answer` vs `describe/reader.py:answer` -- same, same fix.
  - `boundaries.detect` is *not* a collision: `scenes.detect` and
    `speech.detect` are reached qualified and stay that way.
  - `boundaries.grid` IS refused, and is why the verb is `timeline`:
    `boundaries/grid.py` is a submodule, and a package attribute of the same
    name shadows it, so `import falconvar.video_rag.boundaries.grid` would
    stop resolving. `timeline` also pairs with `load() -> Timeline`, so the
    return type is legible from the call.

Two shapes worth arguing about, decided:

  - `boundaries.detect` returns `None` for `uniform`. At the `Produced` level
    CLAUDE.md is emphatic that a policy needing no precursor is an answer and
    not an absence -- but that argument is about a uniform signature across
    HTTP. Here the return type is the document, and the honest document for
    "there are no cuts" is no cuts. `evidence()` keeps returning a `Produced`
    with `skipped: ["evidence"]`, unchanged.

  - `embed.encode` does not resume. Resume is a property of an index -- it
    needs `stored_hashes()` -- and the pure verb has no index. It embeds every
    unit it is given and says so in its docstring. `run()` keeps the per-index
    diff exactly as it is today.

Surface: eight components go from 30 exported names to 38. Each new one passes
the test already applied to `split`, `evidence` and `retune` -- a second way
*in* that no naming collapses into `run`. `Unit` joins them, because it is now
a return type a caller annotates.


2. FRAMES -- the one thing that is not a document
==================================================

New module `falconvar/video_rag/frames.py`, beside the components rather than
inside one, because `video` writes pixels and `describe` reads them and
neither may import the other.

    class Frames(Protocol):
        def put(self, index: int, image) -> None: ...
        def get(self, index: int) -> bytes: ...
        def __contains__(self, index: int) -> bool: ...
        written: int
        bytes_written: int

    class FrameStore(Frames)     the existing one, moved here unchanged apart
                                 from gaining `get`/`__contains__`. Takes a
                                 root, as it already does -- video's driver is
                                 what resolves the root today, and that moves
                                 into `run()`.

    class MemoryFrames(Frames)   a dict of index -> encoded bytes.

`describe/frames.py:FrameSource` stops resolving a path and takes any `Frames`
plus a manifest. Its manifest-walking (`images_for`) is unchanged; only where
the bytes come from changes. `StoreUnavailable` keeps its meaning for both
implementations: a frame the manifest names that the source does not hold.

So the whole pipeline can run in RAM:

    held = MemoryFrames()
    manifest = video.ingest(media, timeline, "uniform", frames=held)
    descriptions = describe.answer(manifest, timeline, held, describer="stub")

and the memory cost is the caller's decision, stated in the docstring: a
minute of 720p at 1 fps is tens of megabytes, an hour is hundreds.

Check before moving: nothing outside `video/` imports `video.store`, and
`recovery/` imports nothing from the pipeline at all (it has its own writer).
Verify, don't assume.


3. WORKSPACE -- two data roots in one process
==============================================

New module `falconvar/workspace.py`.

    class Workspace:
        def __init__(self, data_root=None, weights=None, env_file=None)
        def __enter__ / __exit__          # sets and resets a ContextVar
        .media .audio .boundaries .video .cut .describe .embed .retrieve

    ws = Workspace(data_root="/var/lib/a")
    ws.media.run("talk.mp4")              # bound: this workspace's root

    with Workspace(data_root="/var/lib/b"):
        media.run("talk.mp4")             # module-level call, other root

Mechanism: a `ContextVar` in `paths`, read first in `_resolve`. Precedence
becomes: the active workspace, then `configure()`, then `FALCONVAR_DATA` /
`FALCONVAR_WEIGHTS`, then the checkout, then `~/.falconvar`. A ContextVar
rather than a plain global because it is already per-thread and per-asyncio-
task, so two workspaces cannot bleed into each other under the concurrency
`describe` already runs.

`falconvar.configure()` keeps working exactly as it does now: it sets the
default workspace's roots. Nothing already written changes, and none of the
72 `paths.*` call sites is touched.

The bound attributes are generated over the component list rather than written
out, so adding a component adds nothing here -- the same reason
`service.COMPONENTS` is a table.

Cache invalidation, which is the part that is easy to get wrong. Three caches
are keyed on nothing today and read the data root:

    describe/library.py       `_cache`  reads `paths.PROMPTS`
    aggregates/definitions/   `_cache`  reads `paths.AGGREGATE_DEFINITIONS`
    shared/models/providers   reads `paths.PROVIDERS`

Each becomes a dict keyed by the resolved data root instead of a single slot.
`refresh=True` keeps its current meaning for the API, which needs it after a
write regardless of workspaces.

One honest limitation, to be documented rather than papered over: **API keys
are process-global.** `env_file=` loads that file for the workspace, but keys
land in `os.environ`, which one process has one of. Two workspaces needing
*different* values for `OPENAI_API_KEY` is not supported, and saying so beats a
parameter that looks like it works. (Resolving keys through the workspace
instead of `os.environ` is a bigger change and is not in this plan.)


4. PROGRESS  (plan.txt section 5)
==================================

New `shared/progress.py`:

    @dataclass(frozen=True)
    class Progress:
        component: str          # "describe"
        total: int
        completed: int
        skipped: int
        current: str | None     # "3:clip:text"
        result: Any | None

`on_progress: Optional[Callable[[Progress], None]] = None` is added to the
three components where a run takes long enough to want one, on both the verb
and `run`:

    video.ingest / video.run       per chunk -- `pipeline.ingest` already
                                   takes `on_chunk`; this wires it through
    describe.answer / describe.run per (chunk, sampler) answer
    embed.encode / embed.run       per batch

Two things to state in the docstrings rather than discover:

  - describe's callbacks arrive **out of order**. Calls are gathered under
    `describer.concurrency`, so completion order is not manifest order.
    `completed`/`total` are still monotonic and correct; `current` is whichever
    finished.
  - the callback runs on the event loop. A slow callback serialises the
    gather, so it is for reporting, not for work.

Not doing plan.txt 5(b), the `describe.iter(...)` generator, and the reason is
worth recording: describe's internals are `asyncio.gather` under a semaphore,
so a synchronous generator would have to either serialise the concurrency it
exists to exploit, or buffer through a queue and lose the "stop mid-run"
property that was the point. A callback that can raise gives the same control
without either. If the stopping is what is wanted, `limit=` already does it
and is resumable.

Level 2: `on_step(component, produced)` gains an optional third argument, so
`process` can forward a component's progress. Added with a default so every
existing two-argument callback -- including the API's job runner -- keeps
working untouched.


5. LOGGING  (plan.txt section 8)
=================================

A named logger per component, `logging.getLogger("falconvar.<component>")`,
with a `NullHandler` on `falconvar` so the library configures nothing.

Structured fields via `extra=`: `video_id`, `component`, `event`
(read/write/skip/call/done), `duration_ms`, `artifact`, `reason`.

Levels:

    DEBUG    what was read, what was skipped and why, per-unit timing
    INFO     component started / finished, the headline stats
    ERROR    something failed

One deliberate departure from plan.txt, which proposes WARNING when a setting
is resolved by fallback ("embedder defaulted to openai"). That is not a
fallback in this tree -- `providers.choose` resolving to openai is the
documented default, and `/capabilities.defaults` publishes it. Warning on a
working default trains people to ignore warnings. Those go to DEBUG. WARNING
is reserved for what is already reported-but-continued: the best-effort
Supabase write, and `prompts_error`.

Level 2 logs the pipeline shape, one INFO per component plus a total, which is
the timing breakdown the tier driver currently only has in CLI printing.


6. TYPES  (plan.txt section 2)
===============================

Every document dataclass gets per-field docstrings, and `TYPES.txt` is
**generated from the dataclasses** by introspection, the way
`shared/contracts/schemas.py` already generates the JSON Schemas -- with the
same `--check` mode, so a field added without documentation is a CI failure
rather than a doc that drifts.

Covers: `Media`, `VideoStream`, `AudioStream`, `RawTranscript`, `Cuts`,
`Timeline`, `Manifest`, `Transcript`, `Descriptions`, `Embedded`, `Aggregate`,
`Produced`, `Run`, `Moment`, `Hit`, `Unit`, `Progress`.

plan.txt's field lists were written from memory and several names are wrong --
`Media.fingerprint` is `source`, `Cuts.cut_points` is `cuts`, `Manifest` has
`chunks` and not `frames`. Generating from the code is what stops that
happening again.


7. SINKS AND SEARCH DOCS  (plan.txt sections 7 and 9)
======================================================

The sink support table is **derived, not written**: `sinks.BACKENDS` for what
exists, `rows.WRITERS` for which artifacts have a Postgres representation, and
signature introspection for which components take `sink` at all. Written by
hand it would drift from `sinks.write`, which refuses `supabase` for an
artifact absent from `WRITERS`.

From the code as it stands today, that table is:

    media       file | supabase
    audio       file | supabase        (raw_transcript)
    boundaries  file | supabase        (cuts, timeline -- evidence and run)
    video       file | supabase        (manifest)
    cut         file | supabase        (transcript)
    describe    file | supabase        (descriptions)
    embed       no sink at all -- it writes vectors, and `index_name` is where
    retrieve    reads; no sink

One correction to make while here: `sinks.write` is documented as best-effort
for Supabase, but it only *is* best-effort when an `on_problem` callback is
passed -- otherwise it re-raises. Every component calls it without one. Either
the docstring or the behaviour is wrong; decide which, and make them agree.

Common search patterns go into `retrieve.search`'s docstring and LIBRARY.txt:
all videos, one video, a time window, by question, several named videos, and
reading `notes` when `moments` is empty.


8. VERIFICATION
================

The standing battery, after every step: `schemas --check` 9/9, every module
imports, `example.py` runs, all eight CLIs run, `recovery.recreate` 299/299
byte-identical.

New, and the real oracle for this change:

  a) EQUIVALENCE. The same video through `run()` and through the pure verbs
     must produce byte-identical documents. This is the recreate test applied
     to the refactor: if the two paths disagree, the factoring is wrong. Run
     with `stub`/`hash` backends so it costs nothing.

  b) NO FILESYSTEM. The full chain -- split, listen, detect, timeline, ingest
     into `MemoryFrames`, apply, answer, encode -- with `paths.out_root`
     monkeypatched to raise. It has to complete. That is the claim of this
     whole plan, and it should fail loudly if it stops being true.

  c) TWO WORKSPACES. The same file run under two roots in one process, each
     writing only into its own tree, including the prompt vocabulary
     (different `data/prompts.json` per root) -- which is what catches the
     cache-keying.

  d) IMPORT COST. `import falconvar.video_rag` stays at ~1.3 ms and
     `import falconvar` does not grow. `workspace.py` must not import the
     components eagerly; the bound attributes resolve lazily, as
     `video_rag.__getattr__` already does.


9. ORDER
=========

    1  Frames protocol + MemoryFrames + FrameSource taking one.   (section 2)
       Nothing else can be filesystem-free until pixels are.

    2  The pure verbs, one component at a time, easiest first:
       cut, boundaries, audio, media(no-op), video, describe, embed.
       Each is: move the checks down, define the verb, rewrite `run` to call
       it, export it, run the equivalence test for that component.

    3  Types + generated TYPES.txt.                               (section 6)
       Trivial once the verbs' return types are settled.

    4  Workspace + cache keying.                                  (section 3)

    5  Progress, then logging.                                    (sections 4, 5)
       Logging last because it touches every component and must not be
       tangled with a factoring change while that is being verified.

    6  Docs: LIBRARY.txt rewritten around the two levels and the pure layer,
       the derived sink table, search patterns; CLAUDE.md gains the *why* of
       each decision above.

Steps 1 and 2 are the bulk. Steps 3-6 are additive and none of them can break
an existing caller.
